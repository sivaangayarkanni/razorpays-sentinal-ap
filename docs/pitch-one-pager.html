Sentinel-AP — Autonomous Transaction Reliability Layer

Smart security guardrail between AI buyer agents and Razorpay

Razorpay Buildathon

Deterministic dual-gate middleware so agents can spend — safely, observably, and without stuck payouts.

Problem

  • Hallucinated SKUs & over-budget spends — LLM prompts are not a payment authorization layer.
  • Bank-rail outages fail closed forever or retry blindly, creating stuck / duplicate money movement.
  • No audit trail between agent intent and Razorpay Order — ops & compliance go dark.

Solution — Dual Gate

Gate 1 · Hard Block

Deterministic policy: amount/daily caps, SKU lists, currency allow-list. Codes like SKU_BLACKLISTED, AMOUNT_CAP_EXCEEDED.

Gate 2 · Soft-Fail

Pre-flight bank health (>95%). Degraded → QUEUED; recover → Order → CLEARED. Never pay on a sick rail.

Architecture

Agents never talk to Razorpay directly. Every spend intent hits Sentinel-AP first — auth, idempotency, dual gates, then Orders + Checkout + verify/webhooks.

AI Agent → Sentinel-AP → Gate 1 Policy → Gate 2 Health → Razorpay Order → Checkout · HARD_BLOCK · QUEUED
